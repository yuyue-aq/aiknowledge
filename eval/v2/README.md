# V2 合成资料与 50 题标注集

这是人工设定的虚构产品资料，不含用户私密数据或实际模型结果。

- 50 个独立问题，35 个调优问题、15 个保留验收问题，划分已写入每题 `split`。
- 23 份 TXT 资料，包括正常说明、两个相互冲突的上线时间、一个关闭分类中的合成口令。
- 标准答案、预期行为、访问范围、原文证据区间与 SHA-256 已标注。
- 正常回答的同义问题与直接问题使用同一资料；这两种问法处于同一个数据划分。

## 入库与运行

1. 新建独立测试空间，并在本地测试空间设置 `PRO`（200 份）或 `TEAM` 配额；FREE 上限 20 份不足以导入 23 份夹具。这里是现有测试额度字段，无支付调用。将 01—20 资料放入开放分类，两个 conflict 文件放入仅拥有者可访问的分类，closed 文件放入关闭分类。
2. 等待真实 BGE 编码完成。根据每份资料的当前文档 UUID、版本 UUID，将 `evidence_templates` 映射为 API `evidence_refs`，并核对原文区间与哈希。不得使用虚构 UUID，也不得用检索是否命中来决定标准答案。
3. 通过创建版本的 `case_ids` 分别冻结两个题集：35 题调优集与 15 题验收集。保留验收集不得用于调参。
4. 使用实际异步评测接口运行基线，逐题核对回答和引用并人工评分。
5. 对调优集修复后运行同一题集版本，记录配置、知识清单差异与逐题变化；最后只运行一次保留验收集。
6. 真实分享 token、会话 Cookie、撤销、过期和跨空间访问应另做 API 权限回归，不能由合成 public scope 代替。

`gold_cases.json` 是入库前标注文件，不是可直接 POST 的 API 请求。2026-10-02 已完成真实隔离入库、证据绑定以及 DeepSeek Flash 的35题基线、35题复测和首次15题保留集。报告见 `runtime/DeepSeekFlash真实验收报告.md`；人工回答准确率尚未评分。下述本地检索基线不能替代真实端到端指标。


## 已实测的本地检索（无付费模型）

`local_retrieval_tuning_baseline.json` 使用真实本地 BGE、官方 Transformers CLS pooling、归一化向量和手写 Top K。35 题调优集中 28 题有正向文档标注，文档 Recall@5 / Hit@5 均为 1.0；7 题负例只记录候选，未做生成或拒答评分。15 题保留集未运行。1024 维，耗时 8.335 秒。

这份资料很小且为合成语料，报告不是生产 FlagEmbedding、数据库权限或业务准确率的证据。复现命令见仓库《V2MVP交付说明》。

`ui/` 中的截图和 `ui/setup-fixtures.js` 使用合成接口响应，属于交互验收；其中评分数字不得混入真实评测报告。`runtime/` 中另有真实 API 及模型联调截图，应区分使用。
